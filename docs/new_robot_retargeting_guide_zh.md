# GMR 新机器人重定向接入方法与验收指南

本文总结将 GMR 从双足机器人扩展到 Galbot One Golf 轮式双臂机器人时得到的可复用经验。它不是某个 JSON 字段的说明，而是一套从模型审计、动作语义设计、IK 任务构造，到动态验收的工作方法。

适用对象包括：

- 不同自由度、不同连杆比例的双足人形机器人；
- 轮式双臂、轮式人形和固定基座双臂机器人；
- 带升降柱、腰部、头部或冗余手臂的非标准构型；
- SMPL-X、BVH、FBX 或实时设备提供的人体全局位姿输入。

## 1. 最重要的结论：重定向是动作语义投影，不是关节角复制

人体和机器人通常没有逐关节同构关系。即使两个关节都叫“肩”“腰”或“髋”，它们的旋转轴、零位、活动范围和在运动链中的作用也可能完全不同。因此，新机器人接入时首先要回答：

> 人体这个动作表达了什么意图，机器人应该用自己的哪些能力表达这个意图？

例如：

- 双足机器人的 pelvis 平移和腿部动作共同表达行走；
- 轮式机器人的行走意图应主要投影为底盘 `x/y/yaw`，不能把人体左右髋、膝旋转强行分配给升降或腰部关节；
- 人体的抬手意图可以用肩到肘、肘到腕的空间方向表达，不要求机器人复制人体绝对手腕位置；
- 人体的下蹲对于双足机器人通常由髋膝踝表达，对于带升降机构的轮式机器人则可投影为躯干高度变化。

一个可靠的重定向器至少要分清三层：

1. **源动作语义**：人体根运动、躯干朝向、骨段方向、末端姿态和接触状态。
2. **机器人可表达能力**：底盘、腿、腰、升降、手臂、头部及各自的运动范围。
3. **优化任务与约束**：哪些量必须跟踪、哪些只需近似、哪些自由度应由中性姿态或平滑性约束决定。

先确定这三层，再写 frame 对应关系和权重。仅从机器人 link 名称猜测人体部位，通常会得到“求解成功但看起来不像”的结果。

## 2. 先审计模型，再调 IK

新机器人最常见的问题并不是求解器参数，而是模型理解错误。开始适配前应完成以下审计。

### 2.1 确认实际使用的模型

需要明确运行时加载的是 URDF、MJCF，还是由 URDF 转换过的 MJCF。至少核对：

- 关节树、关节类型和父子关系；
- 每个关节的 `axis`、硬限位和速度限制；
- `qpos`、`qvel` 和 actuator 顺序；
- 根节点是 free joint、平面虚拟关节，还是固定基座；
- 参与 IK 的 body/frame 是否真实存在；
- 可视 mesh 与碰撞模型是否来自同一版本；
- 模型零位是否是可用的中性姿态。

URDF 和 MJCF 的 link 名称相同，不代表两者运动学一定相同。转换过程中可能增加平面底盘关节、改变 root、合并 fixed joint，或者使用另一套 mesh。因此应以运行时模型为准，同时把它和原始 description 包进行结构核对。

### 2.2 做单关节正方向检查

不要只看 URDF 中的轴向文本。最直接的方法是在可视化器中从 `qpos0` 出发，每次只给一个关节增加小角度，例如 `+10°`，记录：

- 对应 link 实际向哪个方向转动；
- 左右关节是否镜像；
- 手臂的肩、肘、腕 link 分别对应运动链的哪个位置；
- 腰部串联轴分别主要影响 pitch、yaw 还是 roll；
- 关节正方向是否符合控制接口约定。

这一步可以在调权重前发现大多数“方向反了”和“关节编号错了”的问题。零位外观看似合理也不能替代单轴扰动测试。

### 2.3 明确所有坐标约定

至少书面记录：

- 世界坐标的 up 和 forward 轴；
- 四元数是 `wxyz` 还是 `xyzw`；
- 输入位姿是全局旋转还是父节点相对旋转；
- rotation offset 是左乘还是右乘；
- root heading 如何从人体 pelvis 旋转中提取；
- 人体和机器人中性姿态分别是什么。

如果整条手臂都向错误象限运动，优先检查坐标系、四元数顺序和 offset 乘法顺序，不要先提高 IK 权重。

## 3. 按机器人形态建立“语义能力映射”

接入前应先写一页语义映射，再写配置。

### 3.1 双足机器人

典型映射为：

- pelvis/root：全身根位置与朝向；
- hip、knee、foot：腿部构型和足端位置/姿态；
- spine/torso：腰部姿态；
- shoulder、elbow、wrist：手臂构型；
- 足接触：地面约束、脚滑和 root 高度修正。

双足机器人的自由根、双腿和地面接触互相耦合，不能只看单帧姿态而忽略支撑关系。

### 3.2 轮式双臂机器人

推荐映射为：

- pelvis 的平面位移和 heading：底盘 `x/y/yaw`；
- spine 高度与相对朝向：升降/腰部机构；
- 人体腿部：通常不直接创建关节姿态任务；
- shoulder→elbow、elbow→wrist：机器人双臂骨段方向；
- wrist/head 相对旋转：低优先级姿态任务；
- 人体垂直动作：在机器人机构允许范围内映射到躯干高度。

底盘只具有平面能力时，必须显式丢弃人体 root 的 roll、pitch 和 z 自由运动，或将 z 交给升降机构处理。让平面底盘跟踪完整 SE(3) 会给求解器制造不可实现目标。

### 3.3 固定基座或自由度较少的机器人

固定基座不应跟踪人体全局平移。更合理的是：

- 将人体动作转换到 pelvis 或 torso 相对坐标；
- 固定机器人 root；
- 优先保留手臂方向和工作空间内的末端意图；
- 对机器人没有的腰、腕或头部自由度显式降级，而不是让相邻关节补偿所有误差。

原则是：**可以主动舍弃机器人无法表达的语义，不能让错误的自由度偷偷承担它。**

## 4. 位置、方向和姿态应按用途选择

不同机器人的比例差异很大。直接跟踪人体全局关节点位置，容易让短臂机器人过度伸展，让长臂机器人收缩到奇怪姿态。

### 4.1 手臂优先使用骨段方向

对肩、肘、腕位置分别记为 `p_s`、`p_e`、`p_w`，先计算人体骨段单位方向：

```text
d_upper   = normalize(p_e - p_s)
d_forearm = normalize(p_w - p_e)
```

再使用机器人自己的上臂和前臂长度 `L_upper`、`L_forearm` 构造目标：

```text
p_elbow_target = p_robot_shoulder + L_upper * d_upper
p_wrist_target = p_elbow_target + L_forearm * d_forearm
```

这种方法保留“手臂指向哪里”和“肘部如何弯曲”，同时自动适配不同臂长。它比统一缩放人体所有关节点更稳健，尤其适合轮式双臂和不同尺寸的人形机器人。

构造目标前必须验证骨段长度非零。缺失 body 或零长度骨段属于输入边界错误，应明确报错，不能静默使用上一帧数据或默认方向。

### 4.2 躯干和头部优先使用相对旋转

机器人躯干应跟随相对底盘的姿态，头部应跟随相对躯干的姿态，而不是复制人体的世界系绝对旋转。相对旋转能够：

- 消除底盘 heading 的重复计算；
- 避免人体整体转身时腰和头再额外旋转一次；
- 方便按机器人能力分别限制 roll、pitch、yaw；
- 保留机器人中性姿态中的固定安装偏置。

旋转限幅应在选定的相对坐标中进行。直接对世界系 Euler 角裁剪，容易在 heading 变化时产生不连续或错误轴向。

### 4.3 末端姿态通常低于位置/方向优先级

人体腕部坐标系与机器人末端 link 坐标系往往没有天然一致性。一个实用优先级是：

1. 上臂方向；
2. 前臂方向或腕部位置；
3. 腕部/工具姿态；
4. 冗余关节的中性姿态。

如果腕姿态权重过高，求解器可能为了满足一个 frame offset 错误的目标而扭曲肩肘。应先证明手臂方向正确，再逐步增加末端姿态权重。

## 5. Frame offset 必须校准，不能靠反复猜符号

人体 body frame 与机器人 link frame 的轴通常不同。rotation offset 的本质是把同一个语义姿态从源 frame 转换到目标 frame。

推荐校准过程：

1. 选择已知的人体中性帧，例如自然站立或 T-pose；
2. 将机器人置于明确的中性 `qpos`；
3. 记录对应人体 body 和机器人 link 的世界旋转；
4. 按代码实际的乘法约定求出 offset；
5. 用至少两个非中性姿态验证，而不是只让中性帧对齐；
6. 单独验证左、右两侧，不假定简单复制或只改一个符号就一定镜像正确。

应把 offset 视为模型标定数据，而不是普通调参。权重只能改变“多努力跟踪”，不能修正错误的 frame 定义。

## 6. IK 任务应分层，并给冗余自由度明确归宿

全身任务一次性丢给求解器并不总是最稳。对底盘、升降腰和双臂耦合的机器人，推荐采用以下顺序：

1. 直接确定底盘的可控 root 自由度；
2. 固定底盘，先求解躯干高度和有限姿态；
3. 基于已经更新的肩部位置重新构造手臂目标；
4. 求解双臂、头部和躯干的组合任务；
5. 应用关节限位安全余量并更新 FK。

这样做的原因是肩部位置依赖升降/腰部结果。如果在躯干尚未就位时只构造一次手臂目标，后续躯干运动会让手臂目标失效。

### 6.1 使用姿态正则化处理不可观自由度

仅约束肘、腕位置时，7 自由度手臂仍有冗余；多轴腰部也可能有多个构型表达相近的躯干位姿。若不给这些自由度偏好，可能出现逐帧漂移或在等价解之间切换。

可使用低权重 posture task，使冗余自由度靠近中性姿态。不同关节可以使用不同权重：

- 不希望参与补偿的关节提高 posture 权重；
- 需要承担语义运动的关节降低 posture 权重；
- posture 权重应低于关键位置/方向任务，避免把机器人锁死在零位。

### 6.2 第一帧与连续帧区别处理

第一帧可能离 `qpos0` 很远，需要较多迭代完成初始化；连续帧有上一帧作为 warm start，通常只需较少迭代。将两者使用同一个迭代预算，要么第一帧不收敛，要么浪费实时计算。

推荐分别配置初始帧和连续帧的最大/最小迭代数，并记录真实运行时间，而不是只根据 solver 返回状态判断实时性。

## 7. 调参顺序比具体权重更重要

建议严格按以下顺序调试：

1. **模型正确性**：joint/link/axis/qpos 顺序和限位正确；
2. **坐标正确性**：世界轴、四元数顺序、全局/相对旋转正确；
3. **语义正确性**：人体意图分配给正确的机器人机构；
4. **几何正确性**：frame offset、机器人骨长和目标锚点正确；
5. **位置/方向权重**：先让主要轮廓正确；
6. **姿态权重**：再增加 torso、head、wrist 的旋转表现；
7. **正则化与限位**：消除冗余漂移和限位饱和；
8. **时间连续性**：最后处理抖动、速度和下游控制可跟踪性。

如果第 2 至第 4 步未通过，继续调权重通常只会得到对少数测试帧的过拟合。

## 8. 约束与平滑不能掩盖错误

### 8.1 关节限位应保留安全余量

输出恰好贴住 URDF 硬限位，在仿真中可能可行，在真实控制器中容易因标定误差、插值或跟踪超调而触发保护。建议给旋转关节保留可配置的安全余量，并同时统计：

- 是否存在越界；
- 距最近硬限位的最小角度；
- 长时间贴近同一限位的帧占比。

安全余量不能替代可达性设计。如果大量关节持续被裁剪，应重新检查目标范围和任务权重。

### 8.2 不要看到大帧差就立刻加速度滤波

挥臂、出拳等动作的源骨段方向本来就可能快速变化。简单输出限速会让机器人动作滞后，甚至让左右手在关键动作点错位。

发现某帧关节增量较大时，应先同时检查：

- 同一帧人体上臂/前臂方向变化是否也很大；
- 大增量是否集中在语义相关关节；
- 是否发生 IK 分支切换或接近奇异位形；
- `p95` 等分位数是否正常，而不是只看全序列最大值。

只有确认变化不是源动作本身，才考虑速度约束、轨迹优化或滤波。时间约束最好进入多帧优化，而不是在错误单帧目标之后做强制低通。

## 9. 验证必须同时包含单帧、序列、指标和视觉

“IK 没报错”和“视频看起来还行”都不足以证明新机器人已经接入正确。建议建立四层验证。

### 9.1 模型级验证

- 模型可加载，`qpos` 维度和顺序符合预期；
- 所有配置引用的 body、joint、geom 均存在；
- `qpos0` 可视化合理；
- 每个关节单轴正方向已检查；
- 左右手臂的链长、frame 和关节限位合理。

### 9.2 合成单帧验证

至少构造：

- 自然站立；
- 双臂前伸；
- 单侧抬臂；
- 左右手明显不对称的姿态；
- 接近但不超过工作空间边界的姿态；
- 缺失 body 或零长度骨段等非法输入。

左右不对称帧特别重要：完全对称的 T-pose 很难暴露左右 frame offset 交换、镜像符号错误等问题。

### 9.3 标准动作集验证

所有机器人应尽量使用同一组源动作，至少包括：

- 站立：检查中性姿态和静态漂移；
- 摆臂：检查肩肘方向、左右镜像和连续性；
- 行走：检查 root/底盘语义与上身解耦；
- 单侧出拳或指向：检查快速动作和左右非对称；
- 下蹲或躯干转动：检查高度、腰部范围和限幅。

参考机器人（例如 Unitree G1）适合作为“动作意图是否一致”的视觉基线，但不是要求新机器人复制其每个关节角。不同构型应该看起来在做同一件事，而不是拥有相同数值。

### 9.4 建议记录的指标

- 输出是否全部为有限值；
- 关节限位最小余量；
- 上臂方向角误差；
- 前臂方向角误差；
- torso/head 相对姿态误差；
- 每帧 `qpos` 增量的均值、`p95` 和最大值；
- 大关节增量与源骨段方向突变是否发生在同一帧；
- 第一帧与连续帧求解耗时；
- 目标帧率下的实时通过率；
- 若用于真实机器人或 RL policy，控制侧是否能跟踪这些速度和加速度。

两个方向单位向量 `u`、`v` 的角误差可以统一计算为：

```text
angle_error = acos(clamp(dot(u, v), -1, 1))
```

方向误差比逐关节角误差更适合跨构型比较，因为它直接衡量动作轮廓是否一致。

## 10. 常见症状与排查路径

### 整条手臂方向相反或转到错误象限

优先检查四元数顺序、world forward/up、rotation offset 乘法顺序和左右 frame 对应。不要通过加负权重或随机改关节符号修补。

### 肩肘位置尚可，但手腕剧烈扭转

通常是 wrist frame 坐标不匹配或末端姿态权重过高。先将腕姿态降权，确认骨段方向，再重新标定末端 offset。

### 多轴腰部或冗余手臂每帧乱动

任务可能没有观测这些自由度。增加合理的 posture task，采用上一帧 warm start，并检查是否在奇异位形附近存在多分支解。

### 轮式机器人升降机构随人体迈腿上下抽动

说明仍在按双足拓扑映射髋膝任务。删除这种直接映射，让升降机构只接收躯干高度或明确的下蹲语义。

### 底盘出现 roll/pitch 或漂浮

平面底盘任务错误地保留了完整 SE(3) root。应投影为 `x/y/yaw`，并固定 ground z。

### 动作很平滑，但总是慢半拍

检查输出速度限制或低通滤波是否造成跟踪滞后。将机器人变化与源动作变化按帧对齐分析。

### 单帧正确，连续视频突然翻转

检查 IK 分支切换、Euler 角跨界、四元数符号处理、接近奇异位形，以及是否每帧错误地从 `qpos0` 冷启动。

## 11. 软件结构上的复用原则

不同机器人之间最值得复用的是数据规范、任务类型和验证工具，而不是某一组 link 映射和权重。

建议将实现分成三类：

- **通用层**：人体输入规范化、缩放、ground offset、四元数转换、IK 求解、限位、指标统计和回放；
- **形态层**：双足、平面移动双臂、固定基座双臂等语义策略；
- **机器人配置层**：frame 名称、链长、offset、限幅、权重和中性姿态。

当新机器人与已有机器人形态相同，优先新增配置；当机器人能力模型明显不同，例如从双足变为轮式升降双臂，才新增小而明确的形态适配逻辑。不要把一个机器人的特殊 frame 名称和常数散落进通用求解流程。

配置加载时应一次性验证关键不变量：

- 引用的 robot frame/joint 存在；
- 必需的人体 body 存在；
- 运动链骨长非零；
- 限幅上下界合法；
- posture 配置只引用有效自由度；
- 机器人 root 类型与所选形态策略相符。

内部流程建立这些不变量后，不需要在每一层反复静默兜底。错误应在真实输入边界尽早、明确地暴露。

### 11.1 本仓库的轮式双臂配置协议

本仓库目前使用 `planar_base` 与 `mobile_upper_body` 两段配置接入轮式双臂机器人。通用代码不依赖 Galbot 或 R1 Pro 的具体 link 名称：

- `planar_base.frame_name/human_body`：底盘 frame 与人体 root；
- `yaw_frame`：人体 heading 坐标约定；
- `torso_frame/torso_human_body`：机器人躯干与人体 spine；
- `torso_local_xy`：中性状态下，躯干相对底盘的平面锚点；
- `torso_height_scale/range`：人体高度到机器人可达高度的投影；
- `torso_orientation_limit_deg`：机器人可表达的相对 roll/pitch/yaw；
- `arm_chains`：每条手臂的 shoulder/elbow/wrist robot frame 和 human body；
- `arm_position_cost`：骨段方向所构造位置目标的权重；
- `elbow_orientation_cost/wrist_orientation_cost`：可选姿态任务；设为零时无需提供末端 orientation frame；
- `joint_posture_cost`：稳定轮组、冗余手臂或不希望参与补偿的关节；
- `joint_limit_margin_deg`：输出距硬限位的最小安全角度；
- `head_frame/head_human_body`：可选；没有独立头部的机器人应省略，而不是填写虚构 frame。

当前协议要求平面机器人的前三个 `qpos` 严格为 `base_x/base_y/base_yaw`。新增模型时需要：

1. 在 `ROBOT_XML_DICT`、`ROBOT_BASE_DICT` 和 `VIEWER_CAM_DISTANCE_DICT` 注册模型；
2. 在 `PLANAR_BASE_ROBOTS` 声明该模型使用前三维平面底盘约定；
3. 新建对应人体格式的 IK JSON，并填写以上两段配置；
4. 从运行时模型 FK 测量上臂和前臂长度，不复制其他机器人的长度；
5. 为该机器人增加合成不对称姿态、限位、未参与自由度和标准动作序列测试。

Galbot One Golf 和 Galaxea R1 Pro 已共同验证该协议：前者有五轴腿腰和独立头部，后者有四轴躯干、三组舵轮且没有独立头部。R1 Pro 案例见 [Galaxea R1 Pro 轮式双臂重定向](galaxea_r1pro_retargeting.md)。

## 12. Galbot One Golf 案例带来的具体启示

Galbot 适配前的配置复用了双足映射思路，把人体髋、膝旋转交给五轴腿腰链，并直接使用不匹配的手臂 frame 姿态。求解器能够输出有限关节角，但可视结果中手臂折到头顶、腿腰链承担了错误语义；在站立、摆臂、行走和出拳动作中，上臂/前臂方向误差曾达到约 `60°–84°`。

改造后的关键点是：

- 底盘只跟随人体 root 的平面位置和 heading；
- 五轴腿腰链只表达躯干高度和受限的相对姿态；
- 不再创建人体髋膝到 Galbot 腿腰关节的伪对应；
- 双臂使用人体骨段方向和 Galbot 自身链长重建目标；
- torso 先求解，再依据更新后的肩部位置重建双臂目标；
- wrist/head 姿态使用较低权重，冗余自由度由 posture task 稳定；
- 第一帧增加迭代，后续帧使用 warm start；
- 最终输出保留 `2°` 关节限位余量。

同一套站立、摆臂、行走和左直拳动作共验证 533 帧后，上臂平均方向误差约为 `1.5°–3.7°`，前臂平均方向误差约为 `0.4°–1.6°`。快速行走和出拳中的最大关节帧差与人体骨段方向突变出现在相同帧，因此没有用强速度滤波掩盖动作本身。

案例实现、运行命令和测试入口见 [Galbot One Golf 轮式双臂重定向](galbot_one_golf_retargeting.md)。动态对比和详细指标位于：

- [G1/Galbot 动态对比视频](../output/galbot_eval/g1_galbot_validation.mp4)
- [连续动作验证指标](../output/galbot_eval/continuous_metrics.json)

## 13. 新机器人接入模板

开始编码前，建议先填写以下模板并提交到机器人专项文档：

```yaml
robot_name: <运行时名称>
runtime_model: <实际加载的 URDF/MJCF>
morphology: <biped | planar_mobile_dual_arm | fixed_base | other>

root:
  robot_dofs: <free joint 或 x/y/yaw 等>
  human_semantics: <pelvis 平移、heading 等>
  discarded_components: <例如 z/roll/pitch>

semantic_mapping:
  locomotion: <机器人如何表达人体移动>
  torso: <高度与相对姿态>
  left_arm: <方向、位置或姿态>
  right_arm: <方向、位置或姿态>
  head: <相对姿态或不跟踪>
  legs: <足端任务、忽略或投影到其他机构>

constraints:
  joint_limit_margin_deg: <数值>
  torso_limits: <数值>
  collision_pairs: <需要时填写>
  contact_policy: <双足需要时填写>

calibration:
  neutral_human_pose: <数据帧>
  neutral_robot_qpos: <qpos>
  frame_offsets: <来源与求法>

validation:
  static_frames: <测试列表>
  motion_files: <统一动作集>
  metrics: <误差、连续性、耗时阈值>
  visual_reference: <参考机器人或人工判定规则>
```

## 14. 完成标准

一个新机器人只有同时满足以下条件，才应认为“完成接入”：

- 模型来源、版本、`qpos` 布局和关节方向有文档记录；
- 映射基于动作语义，而不是仅依赖相似关节名称；
- 静态不对称姿态能证明左右方向和 frame offset 正确；
- 标准动作集中没有 NaN、越界、无语义关节乱动或明显 IK 翻转；
- 关键骨段方向/末端任务有定量误差；
- 关节连续性与源动作变化进行了对齐分析；
- 第一帧和连续帧耗时满足目标场景；
- 有自动化回归测试、对比视频、指标文件和运行文档；
- 原有机器人至少通过一条回归 smoke test，证明通用逻辑没有被新形态适配破坏。

最终判断标准不是“每个机器人输出相同关节角”，而是：**它们受各自机构约束后，仍然清楚地表达了同一个人体动作意图。**
